# Escenario demo recomendado - Donatarias Transparencia

Este escenario está diseñado para una demo comercial/operativa controlada ante una asociación donante. Usa datos cercanos al caso final validado y evita presentar una donación artificialmente perfecta.

## Datos del escenario

| Elemento | Valor recomendado |
| --- | --- |
| Donante | `Asociación Donante Demo Final` |
| Total recibido | `100000` |
| Aplicación 1 | `35000` |
| Aplicación 2 | `30000` |
| Aplicación 3 | `20000` |
| Total aplicado | `85000` |
| Saldo pendiente | `15000` |
| Porcentaje aplicado | `85%` |
| Evidencias | PDF válido de prueba |
| Caso documental | Una aplicación inicia sin evidencia y después se remedia |
| Readiness final | `PARTIAL` por saldo pendiente |

## Secuencia sugerida

1. Iniciar sesión con el usuario autorizado para la demo.
2. Abrir `/donatarias`.
3. Seleccionar `Asociación Donante Demo Final`.
4. Mostrar KPIs: recibido `100000`, aplicado `85000`, saldo `15000`, porcentaje `85%`.
5. Mostrar distribución por tres aplicaciones.
6. Explicar que una aplicación se dejó inicialmente sin evidencia para mostrar remediación.
7. Mostrar evidencia PDF registrada y descargable.
8. Abrir el reporte de transparencia.
9. Imprimir la vista operativa si el flujo de la reunión lo amerita.
10. Cerrar explicando que el readiness correcto es `PARTIAL`, no `READY`, porque existe saldo pendiente.

## Por qué este escenario es útil

### Muestra transparencia

El donante ve el ciclo completo del recurso: recibido, aplicado, pendiente, evidencias y estado de presentación. La conversación se basa en datos visibles, no en explicaciones aisladas.

### Muestra distribución

La donación se presenta como un recurso distribuido en varias aplicaciones. Esto permite explicar montos, beneficiarios o destinos, responsables, estados y proporción sobre el total recibido.

### Muestra evidencia

Cada aplicación puede tener evidencia asociada. La evidencia PDF de prueba permite demostrar carga, consulta y descarga sin usar documentos sensibles ni inventar capturas.

### Muestra saldo pendiente

El saldo pendiente de `15000` hace visible que el seguimiento financiero sigue abierto. Esto refuerza que el sistema no oculta pendientes ni fuerza una lectura de cierre.

### Muestra remediación de faltantes

La aplicación inicialmente sin evidencia permite demostrar una situación realista: el sistema identifica un faltante documental, permite atenderlo desde el contexto correcto y actualiza la lectura documental.

### No aparenta una donación perfecta artificial

El readiness final `PARTIAL` comunica una lectura honesta: hay suficiente información para presentar operativamente el avance, pero todavía existe un pendiente financiero. Esta condición ayuda a sostener una conversación institucional más creíble.

## Mensaje central para el donante

"Este caso muestra cómo FMCPA puede transparentar el avance de una donación sin confundir operación con cumplimiento formal. El sistema presenta lo recibido, lo aplicado, la evidencia registrada y el saldo pendiente; si se requiere un reporte oficial, ese debe pasar por el proceso institucional correspondiente."
